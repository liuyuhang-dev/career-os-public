# 热更机器人 钉钉机器人 — 部署与使用方案

> 本文档面向希望部署和使用这套钉钉机器人的团队，提供完整的从零搭建指引。

---

## 一、产品概述

**热更机器人** 是一款基于钉钉 Stream 模式的团队协作机器人，核心解决游戏/互联网团队的两件事：

1. **热更记录** — 每次发版记录改了什么问题、谁负责、什么时间
2. **Bug 追踪** — 提 Bug → AI 自动分析严重程度和模块 → 写入验收清单

在此基础上，还支持多群独立配置、COS 静态托管、AI 表格云端协作。

## 二、核心功能清单

### 2.1 热更记录

| 功能 | 说明 |
|------|------|
| 录入热更 | 按格式发消息，自动解析日期+条目+负责人 |
| 查询热更 | 查看最近记录、按关键词搜索 |
| HTML 页面 | 生成可分享的热更记录页面 |
| AI 表格同步 | 自动写入热更内容汇总表 |

**录入格式：**
```
@热更机器人 【0521热更内容汇总】
1、登录界面卡顿优化 @张三
2、商城购买逻辑修复 @李四
3、新手引导流程调整 @王五
```

### 2.2 Bug 追踪

| 功能 | 说明 |
|------|------|
| 创建 Bug | `bug 描述 @指派人`，支持附带截图 |
| AI 智能分析 | 自动识别严重程度(P0-P3)、所属模块、风险等级、是否阻塞发版 |
| 查询列表 | 支持按状态筛选（待处理/处理中/已解决） |
| 关闭 Bug | 一句话关闭指定 Bug |
| 验收清单 | 每个群独立 Sheet，按群组隔离 |
| 图片上传 | 自动上传截图并关联到 Bug 记录 |

**创建 Bug 格式：**
```
@热更机器人 bug 登录界面在弱网环境下偶现白屏 @张三
```

**AI 分析返回示例：**
```
🤖 AI智能分析
🔴 风险等级: 高
🚫 阻塞发版: 是
💡 测试建议: 重点测试弱网环境下的登录流程...
```

### 2.3 群组管理

| 功能 | 说明 |
|------|------|
| 初始化验收清单 | 为当前群创建专属 Bug Sheet |
| 验收清单状态 | 查看当前群已绑定的 Sheet |
| 多群隔离 | 不同群组数据互不影响 |

## 四、部署前提条件

### 4.1 基础设施

| 项目 | 要求 |
|------|------|

| Python | 3.8+ |

## 五、部署步骤

### 步骤 1：创建钉钉应用

1. 登录 [钉钉开放平台](https://open.dingtalk.com/)
2. 进入「应用开发」→「企业内部开发」
3. 点击「创建应用」，填写基本信息
4. 在「应用功能」中，开启「机器人」能力
5. 消息接收方式选择 **Stream 模式**（无需配置回调地址）
6. 记录 `Client ID` 和 `Client Secret`

### 步骤 2：准备 Python 环境

```bash
# 安装 Python 依赖
pip install dingtalk-stream requests qcloud-cos-python-sdk-v5 sqlite3

# 或使用 requirements.txt（需要自己生成）
```

### 步骤 3：配置机器人代码

创建项目目录并放置代码文件：

```
dingtalk-bot/
├── bot.py              # 主程序
├── handlers.py          # 业务逻辑
├── db.py               # SQLite 操作
├── dingtalk_utils.py   # 钉钉 API
├── html_gen.py         # HTML 生成
├── cos_utils.py        # COS 上传
├── coze_utils.py       # Coze AI
├── aitable_config.json # 配置文件（需手动创建）
└── bot.db              # SQLite 数据库（自动生成）
```

### 步骤 4：配置参数

创建 `aitable_config.json`，填入你的实际参数：

```json
{
  "hotupdate_base_id": "你的热更记录表baseId",
  "hotupdate_sheet_name": "热更记录",
  "bug_base_id": "你的Bug表baseId",
  "operator_id": "你的unionId（操作员）",
  "coze_bot_id": "你的Coze Bot ID",
  "coze_pat": "你的Coze PAT",
  "group_sheets": {}
}
```

### 步骤 5：修改钉钉凭证

在 `bot.py` 和 `dingtalk_utils.py` 中填入你的钉钉 Client ID 和 Secret：

```python
DINGTALK_CLIENT_ID = "你的Client ID"
DINGTALK_CLIENT_SECRET = "你的Client Secret"
```

### 步骤 6：配置腾讯云 COS（可选）

在 `cos_utils.py` 中填入你的 COS 凭证：

```python
COS_SECRET_ID = "你的SecretId"
COS_SECRET_KEY = "你的SecretKey"
COS_BUCKET = "你的Bucket名称"
COS_REGION = "ap-guangzhou"  # 或你的实际地域
```

### 步骤 7：配置 Coze AI（可选）

在 Coze 平台创建 Bug 分析 Bot，然后通过命令配置：

```
@热更机器人 配置coze <BOT_ID> pat_<TOKEN>
```

### 步骤 8：启动服务

```bash
# 测试启动
python3 bot.py

# 守护进程（推荐）
nohup python3 bot.py > bot.log 2>&1 &

# systemd 服务（生产环境推荐）
# 将 dingtalk-bot.service 复制到 /etc/systemd/system/
sudo cp dingtalk-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable dingtalk-bot
sudo systemctl start dingtalk-bot
```

### 步骤 9：验证部署

在钉钉群里 `@热更机器人`，发送「帮助」，应返回使用说明。

## 六、AI 表格字段设计

### 热更记录表（baseId: 你的热更表ID）

| 字段名 | 类型 | 说明 |
|-------|------|------|
| 标题 | 文本 | 热更日期 + 内容摘要 |
| 热更日期 | 日期 | 格式 YYYY-MM-DD |
| 模块 | 文本 | 所属模块 |
| 内容 | 文本 | 详细描述 |
| 负责人 | 文本 | 多人用逗号分隔 |
| 录入人 | 文本 | 录入者 |

### Bug 验收清单表（baseId: 你的Bug表ID）

每个群初始化后会创建独立 Sheet，字段如下：

| 字段名 | 类型 | 说明 |
|-------|------|------|
| 标题 | 文本 | 【模块】+ 描述摘要 |
| 模块 | 文本 | Bug 所属模块 |
| 描述 | 文本 | 详细描述 |
| 优先级 | 单选 | P0 / P1 / P2 / P3 |
| 状态 | 单选 | 待处理 / 处理中 / 已解决 / 已关闭 |
| 指派人 | 文本 | 负责修复的人 |
| 报告人 | 文本 | 提交 Bug 的人 |
| 图片 | 附件 | Bug 截图 |
| 创建时间 | 日期 | 毫秒时间戳 |

## 八、配置检查与故障排查

### 常见问题

**Q: 机器人没有响应**
- 检查服务器网络能否访问钉钉 API
- 检查 Client ID / Secret 是否正确
- 查看 `bot.log` 日志

**Q: AI 表格写入失败**
- 确认应用已开通 AI 表格读/写权限
- 确认 operator_id（unionId）有编辑权限
- 使用 `@热更机器人 检查配置` 查看状态

**Q: COS 上传失败**
- 确认 COS Bucket 已开启静态网站托管
- 检查 SecretId / SecretKey 权限
- 确认 Bucket 地域与代码中的 Region 一致

**Q: Coze AI 分析失败**
- 确认 Coze Bot 已发布上线
- 确认 PAT 未过期
- 使用 `@热更机器人 检查coze` 查看状态

## 九、定制建议

如果你想基于这套代码做二次开发：

| 方向 | 说明 |
|------|------|
| 去掉 AI 分析 | 删除 `coze_utils.py` 相关调用，handlers 中降级为默认优先级 |
| 去掉 COS | 删除 `cos_utils.py` 调用，HTML 只本地存储 |
| 换成飞书 | 钉钉 API 替换为飞书 SDK |
| 换成其他数据库 | 改 `db.py`，SQLite → MySQL / PostgreSQL |
| 添加新功能 | 在 `handlers.py` 添加新 handler，在 `get_handler()` 中注册路由 |
