# merge-ai 工作流框架（脱敏版）

> 这不是“AI 帮我写代码”，是**把一条软件开发流水线拆成 6 个常驻角色，用 Issue 和 Label 串起来，人只在闸门签字**。
> 这里放的是框架本身：工作约定、6 个角色定义、流程文档、运行时代码、技能索引。

## 角色分工

```
需求（PR）──→ 逻辑层（LL）──→ 表现层（PL）
   │              │                │
   └──→ 工单 ─────┴──→ 测试（LL-TEST / PL-TEST，只读）
                          │
                     BUG / 日报 / GIT（调度与记录）
```

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 需求（PR） | 整理需求、写知识库、拆需求单、提 MR | 不做实现 |
| 逻辑层（LL） | 改 Rust/Bevy 逻辑、写测试 | 不改表现层 |
| 表现层（PL） | 改 Unity/C#、拼界面 | 不改逻辑规则 |
| 工单 | 建单、派发、改状态 | 不判断业务对错 |
| GIT | 分支、提交、MR、冲突核对 | 不替业务拍板冲突 |
| 日报 | 汇总进度、发通知 | 不改代码 |

## 核心机制（框架的“骨架”）

1. **Issue 当数据库，Label 当状态机**：任务状态就是 label 组合，人和 agent 看同一个东西。
2. **2 分钟轮询 + 幂等去重**：去重键是 `(issueId, 最后评论时间)`；不用 webhook，因为内网丢一次就静默卡死。
3. **职责分离**：测试 agent 只读，不许提交代码；防止“自己出题自己判卷”。
4. **人工闸门**：标签为「人工」的 issue 一律不派发，必须等人确认。
5. **失败自愈**：探活失败 → 回滚 main → 重启；无人值守时可用性优先。
6. **工作区隔离**：每个角色一个工作区、一个分支，不共享、不额外建 worktree。

## 没有带出来的

- 30 个 `axiom-*` 技能的完整内容（含公司内部契约、知识库 API、页面/模块规则）；
- 业务代码（Rust/Bevy、Unity/C#、CSV 配置）；
- 知识库数据、issue 记录、CI 配置、部署凭据。

所以这份是**可读、可讲、可照着搭**的框架，不是能直接启动的完整系统。
