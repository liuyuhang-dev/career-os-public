# 游戏测试实习生月度考核标准（关卡方向）

> **适用对象**：关卡方向测试实习生  
> **试用期**：6个月 | **考核频率**：每月一次  
> **评估人**：PM（主评，最终裁量）+ 导师（单独加权）+ 主策划或主程序（交叉评估）  
> **通过线**：60分及格，<60当月淘汰，无延期试用 | **优秀线**：80分以上  
> **考核结果挂钩**：是否继续留用/优化 | **反馈形式**：口头沟通

---

## 一、考核维度与权重总览

| 大类 | 权重 | 维度 | 分权重 | 说明 |
|------|:---:|------|:-----:|------|
| **硬性能力** | 60% | 测试执行力 | 25% | 用例质量、缺陷发现、回归效率、禅道规范性 |
| | | 关卡功能掌握 | 15% | 关卡测试覆盖、关卡编辑、探索性测试 |
| | | 工具与效率 | 10% | Python/自动化、工具运用、文档沉淀 |
| | | 游戏理解与审美 | 10% | 重度玩家感、关卡品质判断、审美力 |
| **软性能力** | 40% | 自驱力与主动性 | 15% | 主动揽活、不催不拖、自主发现问题 |
| | | 沟通与协作 | 10% | 表达清晰、缺陷描述精准、跨角色配合 |
| | | 学习与成长 | 10% | 技能提升斜率、举一反三、反馈消化 |
| | | 责任心与严谨 | 5% | 找茬精神、质量执着、不放过细节 |

## 二、月度评分节奏

| 月份 | 阶段定位 | 侧重 |
|:---:|------|------|
| M1 | 入职适应期 | 学习速度、基础工具上手、导师配合度 |
| M2 | 独立起步期 | 独立执行用例、Bug规范提交、关卡理解入门 |
| M3 | 稳定产出期 | 缺陷质量、关卡编辑上手、沟通协作成熟度 |
| M4 | 深度提升期 | 探索性测试、Python/自动化应用、审美判断体现 |
| M5 | 全面独立期 | 独立负责模块、文档沉淀、主动改进流程 |
| M6 | 综合答辩期 | 6个月全景回顾 + 自述报告 + 交叉评估汇总 |

## 三、各维度评分细则

> **注意**：不设绝对 Bug 数量基线，侧重 Bug 质量而非数量——以有效性、严重度、描述规范性、是否推动修复闭环为准；部分 Bug 质量评判需结合导师与交叉评估人意见。

### 硬性能力（60%）

#### 1. 测试执行力（25%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 独立设计高质量用例，核心场景覆盖全面无盲区；发现的缺陷有效且有一定深度（非表面UI问题）；回归测试自动化落地，效率提升可量化；禅道使用规范，缺陷单描述精准，开发极少打回 |
| 良好 | 75-84 | 用例设计合理，覆盖主要功能路径；缺陷发现稳定，能兼顾功能与边界场景；回归执行及时无遗漏；禅道使用无明显规范问题 |
| 合格 | 60-74 | 用例需导师Review后可用，覆盖面有提升空间；能发现基本功能问题但对边界/异常场景敏感度不够；回归基本完成；禅道偶有遗漏字段或状态更新不及时 |
| 不合格 | <60 | 用例质量差需大量返工；缺陷发现极少或大量无效/低质Bug；回归漏测导致线上问题；禅道使用混乱 |

#### 2. 关卡功能掌握（15%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 关卡功能测试全面无死角；能自主进行探索性测试发现隐蔽问题；关卡编辑独立操作，输出可用的关卡调整建议；对关卡设计逻辑有自己的理解并能与策划对话 |
| 良好 | 75-84 | 关卡测试覆盖主要功能点；探索性测试有产出；关卡编辑在导师指导下可完成基本操作 |
| 合格 | 60-74 | 关卡测试按用例执行无误；了解关卡编辑基本操作但尚不能独立完成；探索性测试意识有待加强 |
| 不合格 | <60 | 关卡功能漏测严重；无法理解关卡编辑基本概念；不玩不理解所测游戏 |

#### 3. 工具与效率（10%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | Python脚本实际应用于测试数据构造或自动化，效率提升可量化；工具运用熟练且能根据场景选择最优方案；累计输出 ≥1份可复用文档或自研小工具 |
| 良好 | 75-84 | 工具使用熟练，能根据场景选择合适工具；文档沉淀及时、格式规范 |
| 合格 | 60-74 | 基本工具使用无障碍；文档有时需提醒补充 |
| 不合格 | <60 | 工具操作频繁需要他人帮忙；文档缺失或敷衍 |

#### 4. 游戏理解与审美（10%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 深度体验所测游戏，能提出有见地的关卡体验反馈；对同类竞品有关注和对比分析；审美判断被策划/美术认可 |
| 良好 | 75-84 | 游戏体验投入，能识别关卡趣味性/难度/节奏问题；对画面/UI有不依赖他人的判断 |
| 合格 | 60-74 | 愿意玩游戏但深度不够；审美判断需要导师引导 |
| 不合格 | <60 | 对所测游戏缺乏兴趣；无法区分好坏关卡；审美判断基本为零 |

### 软性能力（40%）

#### 5. 自驱力与主动性（15%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 不等派活，主动寻找测试盲区；发现流程问题主动提出改进建议并被采纳；学习计划自主制定且超额完成 |
| 良好 | 75-84 | 任务完成后主动询问下一项；遇到问题先自己尝试解决再求助；学习计划按节点完成 |
| 合格 | 60-74 | 能完成分配任务，但不会主动拓展；需要导师定期push；学习进度基本跟得上 |
| 不合格 | <60 | 催一下动一下，被动等待；遇阻即放弃不尝试；学习滞后明显 |

#### 6. 沟通与协作（10%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | Bug描述精准，开发一看就懂不再追问；与策划/开发沟通顺畅，能推动问题解决；交叉评估中主策划/主程序评价积极 |
| 良好 | 75-84 | Bug描述清晰，偶有细节需补充；团队沟通无摩擦 |
| 合格 | 60-74 | Bug描述基本到位但偶有模糊；存在沟通不畅但可纠正 |
| 不合格 | <60 | Bug描述不知所云，开发频繁打回；沟通态度有问题或协作冲突 |

#### 7. 学习与成长（10%）

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 月度技能增长肉眼可见；能举一反三，学到A能推理出B；对反馈不重复犯错，改进速度远超预期 |
| 良好 | 75-84 | 学习曲线正常上升；同类错误不犯第二次；对新工具/新方法接受快 |
| 合格 | 60-74 | 学习速度一般但能跟上节奏；同类问题偶有反复但整体在进步 |
| 不合格 | <60 | 学习停滞，同样问题反复出现；对新知识抵触或敷衍 |

| 等级 | 分数区间 | 行为标准 |
|:---:|:---:|------|
| 优秀 | 85-100 | 对自己测过的功能有"质量兜底"意识；线上出问题第一时间响应复盘；不放过任何一个可疑点，宁可多确认也不放过 |
| 良好 | 75-84 | 测试认真仔细，漏测率低；对Bug状态主动跟进到底 |
| 合格 | 60-74 | 基本认真但偶有疏忽；需要导师提醒关注边界Case |
| 不合格 | <60 | 敷衍了事，明显走形式；漏测导致线上事故；Bug跟踪半途而废 |

## 四、评分计算

### 4.1 总分公式

```
PM评分 = Σ(各维度得分 × 分权重)

硬性部分 = 执行力得分×0.25 + 关卡掌握得分×0.15 + 工具效率得分×0.10 + 游戏审美得分×0.10
软性部分 = 自驱力得分×0.15 + 沟通协作得分×0.10 + 学习成长得分×0.10 + 责任心得分×0.05
PM评分 = 硬性部分 + 软性部分
```

### 4.2 多方评分合成

```
月度总分 = PM评分 × 0.50 + 导师评分 × 0.30 + 交叉评分 × 0.20
```

| 评分来源 | 权重 | 说明 |
|:---:|:---:|------|
| PM | 50% | 全维度打分，拥有最终裁量权 |
| 导师 | 30% | **单独加权**，基于日常带教观察，全维度打分 |
| 交叉评估 | 20% | 由主策划或主程序对沟通、协作、Bug质量、游戏理解四个简化维度打分 |

> PM 评分与导师评分出现显著偏差（≥20分）时，PM 须与导师当面校准后确定最终分数。

### 4.3 结论与动作

| 总分 | 结论 | 动作 |
|:---:|:---:|------|
| ≥80 | 优秀 | 重点培养，记录亮点 |
| 60-79 | 通过 | 正常推进，下月关注短板 |
| <60 | 淘汰 | 当月结束试用 |

---

## 五、实习生自评环节

每月考核前，实习生须先完成自评：

- **自我评分**：对照 8 个维度给自己打分（不参与总分计算，仅作对比参考）
- **本月总结**（300字以内）：
  - 本月完成了哪些工作
  - 觉得做得最好的一项是什么
  - 遇到的最大困难是什么
  - 下个月最想提升的一个方向
- 自评与 PM/导师评分偏差 ≥15 分的维度，考核面谈时重点对齐认知

---

## 六、交叉评估机制

- 每月 PM 指定 **1名导师 + 1名主策划或主程序** 参与评估
- 交叉评估人（主策划/主程序）对以下 **四个简化维度** 打分：
  - 沟通清晰度（对应维度6）
  - 协作配合度（对应维度5/6）
  - Bug质量感知（对应维度1）
  - 游戏理解（对应维度4）
- 交叉评估结果按 20% 权重计入月度总分

---

## 七、逐月门槛（加速淘汰红线）

以下情况当月 **直接判定不合格**，无需等待分数汇总：

| 红线 | 说明 |
|------|------|
| 连续2个月自驱力 <60 | 软性不过关、态度问题，不留 |
| 单月漏测导致线上事故 | 严重P0/P1级别漏测 |
| 虚假汇报 | 虚报Bug数量、伪造测试结果 |
| 严重协作冲突 | 被多人投诉且属实 |
| M3后仍无法独立执行用例 | 学习曲线严重不及预期 |
| M4后关卡编辑仍零基础 | 关卡方向核心能力不达标 |

---

## 八、考核流程总览

```
每月流程：
  实习生自评（考核前3天提交）
    → PM + 导师 + 交叉评估人分别评分
    → PM汇总计算月度总分
    → PM与导师校准偏差（如有）
    → PM与实习生一对一口头沟通结果
    → 告知：通过/优秀/淘汰
```

---

> 📅 此标准从实习生入职第一天同步给本人，确保预期对齐。
