## 零、GM 命令卡(本文档通用)

| 命令 | 作用 | 说明 |
|---|---|---|
| `syncranking` | 同步排行榜并打印当前全部名次(带[ActRankingRobot]标签) | 查机器人分数/名次用它; 日志筛选该标签 |

## 一、验收清单: 3 个疑似真实问题(优先执行)

自动化测试暴露的 3 个「实现 vs 用例」差异, 请逐条人工验收, 结论三选一: **确认是缺陷 / 实际正常 / 用例文档过期**。

### A-1. 已通关卡的重复进入与连胜倍率（⚠ 前提已澄清 · 验证口径已修订）

> **2026-08-29 更新**: 经确认，本游戏关卡为**递进式**，不允许回退，一关只能打一次。
> 原验证路径「回打旧关卡重复通关」在正常游玩中**不存在** → 自动化暴露的「连胜无首通校验」**不构成可利用漏洞**：
> 每次胜利天然都是首次通关，实现「胜即连胜+1」与设计自洽。
>
> **结论（暂定）**: ✅ 实现与设计一致；
> 原用例 TR-SCORE-019、TR-STREAK-009（"非首次通关不提升/不累加连胜"）**前提不成立** → **回流策划**：建议删除，或改写为"中途退出后重进未通关关卡"口径。

**替代验证（2 项，仍需你执行）**:
1. **入口封死校验（客户端侧闭环）**: 打开关卡选择界面，确认**已通关卡不可再点击进入**（按钮置灰/隐藏/提示已通关）。
   → 若已通关卡仍可进入并取得胜利 → 原"连胜刷取"漏洞复活，**立即升级为 P0 缺陷**（录屏）。
2. **中途退出重进（即 TR-SCORE-020）**: 在某个**未通关**的关卡中途主动退出 → 重新进入同一关并通关。
   → 预期：本局按 x1 计分、连胜中断（退出按失败处理，与 TR-STREAK-007 规则一致）。

**服务端侧提醒**（超出客户端手工范围，报给服务端同学）：若存在伪造「关卡结果」请求攻击面，服务器需校验该关卡是否为该用户首次通过（对应 TR-SCORE-024 / TR-SEC-004 口径），否则递进规则可被伪造请求绕过刷连胜。

### A-2. 追分机器人目标分比例超出用例上限

- **对应**: TR-BOT-005 | **风险**: 数值节奏
- **用例预期**: 目标分 = 玩家分 × [1.05, 1.15]
- **实现线索**: 配置实况两档: 1.2~1.3 与 1.05~1.1, 前档超出用例上限

**执行步骤**:
1. `setuserscore 1000` 设玩家分数为整1000
2. 达到触发名次(前2名)后等待/触发追分机器人启动
3. 等追分机器人停止追分(到达目标), `syncranking` 记录其最终分数 S
4. **计算**: 比例 = S ÷ 1000
5. **判定**: 比例 ∈ [1.05, 1.15] → ✅; 比例达 1.2~1.3 → ❌口径不一致(记下具体比例值, 找策划裁决是配置改了文档没更, 还是配错)

### A-3. 同分时玩家排在机器人后面(排序规则相反)

- **对应**: TR-RANK-008/009 | **风险**: 同分结算公平
- **用例预期**: 同分先按达分时间早者前, 完全同刻按**用户ID升序**(玩家=0应最靠前)
- **实现线索**: 排序器按 **ID 降序**(机器人压玩家), 且无达分时间维度

**执行步骤**:
1. `syncranking` 找一个机器人, 抄下其分数 S
2. `setuserscore <S>` 设成与该机器人完全同分
3. 打开排行榜看自己与该机器人先后顺序
4. **判定**: 你在前 → ✅; 机器人在前 → ❌规则与用例相反(截图) → 找策划裁决最终规则

### A-4. 跨天连环胜不断连胜（策划 2026-08-29 点名新增）⭐

> **策划关注点**: 跨天后连胜是否会被误清零、倍率是否被重置回 x1。
> **代码静态排查结论（2026-08-29）**: `successCount` 全部归零点只有 3 处——关卡失败 / 整期首次参与那局 / AddScore(_,false) 分支，
> **均与"天"无关**；存档恢复(OnResume)原样读回连胜。静态上**不存在跨天重置路径**。
> ⚠ 概念区分: **跨天**(72h 期内的自然日切换)连胜**不应**断; **跨期**(过 72h 期边界开新期)数据全重建属**正常设计**, 不算失败。

**执行步骤**（核心路径 + 变体共 4 条）:

**① 跨天重登主验证（隔夜一次）**
1. 晚上（如 23:30）连续通关 2~3 个新关卡，把倍率打到高档位（如 x5），记录连胜数与倍率预告
2. 直接退出游戏（正常退出，不杀进程），**不通关卡**
3. 次日早上重新登录 → 看排行榜连胜数与倍率预告
4. **判定**: 连胜数与倍率档位与昨夜一致 → ✅；被清零/回到 x1 → ❌录屏报缺陷
> 没有隔夜条件时可用 GM 改时间模拟：DEBUG 包改设备时间 +24h 后重登（对照组：TR-LIFE-010 已验证倒计时不受本地时间影响，故此法仅验证客户端展示链路，最终以真实跨天为准）

**② 跨天零点在线穿越（可选，覆盖"0点瞬间"）**
1. 23:58 在线且连胜中（不打关），停留至 00:05 跨过自然日
2. 期间不退出游戏，观察排行榜/进关面板的连胜与倍率
3. **判定**: 无任何变化 → ✅

**③ 跨天当天首局胜利（覆盖"跨天后第一局计分"）**
1. 接①，跨天重登后打**一个新关卡**并获胜
2. **判定**: 本局按**跨天前的高倍率档位**计分（如昨夜 x5 → 本局得分=1×关卡倍率×5），连胜继续 +1 → ✅
   若本局突然按 x1 计分或连胜从 1 重新算 → ❌录屏

**④ 跨期对照（确认"归零"只发生在期边界）**
1. 活动最后一小时打到高倍率，等跨过 72h 期边界进新期
2. **判定**: 新期积分/连胜/倍率**全部归零** → ✅正常设计（跟策划口头确认过口径即为"正常"）；若期内任何时点出现归零 → ❌
