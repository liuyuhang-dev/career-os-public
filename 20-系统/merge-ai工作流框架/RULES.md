# 通用规则

工程级基础通用规则，以 Markdown 表格维护。`id` 递增，`tags` 多个用逗号分隔；其余表头自动作为扩展字段。

| id | title | description | tags | 来源 |
| --- | --- | --- | --- | --- |
| G001 | 刷新时间必须有权威时间源 | 任何「到点刷新 / 倒计时 / 限购重置」若以客户端本地时钟为准，则改系统时间即可提前刷新或延长周期。需求必须写明：使用服务端时间、还是接受单机本地时间；若为本地时间，需明确是否做回拨/快进检测。 | 时间,防篡改,刷新 | 商店 SHOP-006 |
| G002 | 「每日 0 点」必须写明时区 | 只说「每日 0 点刷新」会产生歧义：按 UTC 边界计算在 UTC+8 即本地 08:00。需求应写明「本地 0 点 / UTC 0 点 / 服务器 0 点」，并给出跨时区玩家的表现。 | 时间,时区,刷新 | 商店 SHOP-005 |
| G003 | 界面连点窗口不得长于逻辑幂等窗口 | 界面若比逻辑层更久地拦截重复点击，玩家在两者差值区间内点击会「毫无反应」。要么窗口对齐，要么给出「处理中」可见反馈。 | 重复,幂等,交互 | 商店 SHOP-007 |
| G004 | 刷新清零必须服从 resetRule | 任何「刷新 / 重置」都只清 `resetRule` 允许清零的数据；`never` 项必须保留已购/已用次数。测试需同时验 daily、refresh、never 三种取值。 | 数据一致性,配置 | 商店 ST-D-08 |
| G005 | 设计节点名与 prefab 节点名不一致需登记 | 当设计（pages/*.json）与实际美术 prefab 节点名不同，必须指定唯一权威名并登记兼容路径；否则界面代码的 `Find` 会静默失败，表现为「美术占位文案残留」。 | 设计一致性,界面 | 商店 SHOP-001/018 |
| G006 | 页面的 states 若仅为描述性状态需显式声明 | 页面设计里的 `states`（如 sold-out / refreshed）若不由代码切换，必须注明「由数据驱动、不切换 state」，否则测试无法判断「未切换 state」是缺陷还是设计约定。 | 设计一致性,状态 | 商店 SHOP-016 |
| G007 | 列表格数上限要留可测边界 | 固定 N 格展示 + 配置最多 N 行的组合会让「不足 N 格隐藏」「超出不展示」永远测不到。需求需说明是否允许配置行数与格数不一致，并给出构造方式。 | 可测性,配置,列表 | 商店 ST-C-01 |
| G008 | 硬编码文案必须在多语言需求中显式豁免 | 价格（`×100`）、倒计时（`x天x时`）等若硬编码，多语言下会出现语言混排。若确认不翻译，需在需求中写明例外，避免被反复当缺陷提。 | 多语言,文案 | 商店 SHOP-010 |
| G009 | 占位配置必须标注「本期不可测」 | 字段存在但为占位值（如 `costGrowth=0`、`adFreeCount=1`）时，对应功能不可验证。需求或配置说明中应标注占位及补齐时间，测试用例同步标「不可测」。 | 配置,可测性 | 商店 SHOP-012 |
| G010 | 整页复用宿主 HUD，不自绘资源栏，且不得用「裁压暗底」提亮 | 覆盖在 Home 之上的整页（商店 / 图鉴等）若在 `canvas` 下自绘 `topbar` 复刻一份货币栏，会与宿主 HUD 重叠，每页还要再绑一次体力 / 金币 / 钻石。约定：页面不自绘资源栏，改由把页面名加进 `UiPageLayerStack.HudPages`、由 `MainHudLayerSystem` 把宿主顶栏（Home `canvas/topbar` / GameMerge `canvas/safeview/topbar`）抬到整页弹层之上（实现与口径见 `pages/RULES.md` 第 9 条）；压暗底（`canvas/BG`）保持全屏、整屏变暗，**禁止用「把压暗底顶部裁到 y=320」来提亮**——那会让顶部整条（游戏世界 + 整套 HUD）一起变亮。设计源（`pages/*.json`）与 prefab 是两份产物，删 `canvas/topbar` 必须两边同时删，否则设计器一重导就带回来。检查 `npm run check:page-hud`。 | 设计一致性,界面,HUD | #537 / #539 |
