# 专属版本测试用例集(版本验收 / 回归 / 冒烟)

**这套用例回答两个问题:**

1. **主题一:版本更新的内容如何验收、如何测试?** —— 见「版本验收流程」「版本差异用例的生成规则」「发版门禁」与文末的四条版本级用例。
2. **主题二:如何回归以前的功能、如何冒烟?** —— 见「回归集构成」「影响面选集矩阵」「冒烟集」。

**与基线集的关系:** 通用基线(`baseline-suite.md`)是**回归集的主体**,本文件不重复定义基线用例,只定义:
版本增量的验收方式、版本特有的用例(更新链路、覆盖安装、版本号一致性)、跑哪些基线的选集策略、冒烟清单与发版门禁。
**回归集 = 全量基线 + 版本级用例(本文件)+ 历史缺陷固化用例(EXP-*)+ 探索发现固化用例。**

---

## 规约(与基线集相同,重申三条)

1. **玩与判分离。** 执行轮只产截图与观测值;判定由代码或独立判定轮完成。
2. **期望不能来自观察。** 版本新功能的期望只能来自该版本的需求文档或配置表;没有需求文档时**先拆需求,再写用例**,不许边看游戏边写期望。
3. **没证据不许判通过。** 未实现的能力返回 `skipped` / `blocked`,执行率如实上报。

# 主题一:版本更新的验收

## 版本验收需要什么输入

| 输入 | 谁提供 | 用途 |
|---|---|---|
| 候选包(可安装 / 微信开发版或体验版) | 研发 | 被测对象 |
| 版本号与变更清单 | 研发 / 策划 | 判断哪些用例必跑、哪些可以缓 |
| 该版本的需求文档 | 策划 | 生成版本差异用例(REQ-VER-*)的唯一合法期望来源 |
| 配置表变更明细 | 策划 | 配置 × 运行时交叉(INV-CFG-C01 等) |
| 性能基线 | 测试 | 启动耗时 / FPS / 内存比对 |
| 回归集批准记录 | 测试负责人 | 哪些用例是「必须跑」 |

## 版本验收流程(六步)

| # | 步骤 | 动作 | 产出 |
|---|---|---|---|
| 1 | 变更盘点 | 逐条读变更清单,标出受影响模块(**影响面**)与「无法定位影响面」的变更 | 影响面清单 |
| 2 | 生成版本用例 | 按「版本差异用例生成规则」把每条版本需求拆成 REQ-VER-* 用例 | `specs/` 增量 |
| 3 | 用例复核 | 人逐条批准 / 驳回(唯一的人工用例关卡) | `review-sheet.md`,`state=approved` |
| 4 | 冒烟 | 在候选包上跑冒烟集(见主题二) | 冒烟结论;不过不许进全量 |
| 5 | 全量回归 | 全量基线 + 版本用例 + 按影响面加选的专项 | 运行结果与证据 |
| 6 | 判定与门禁 | 判定、提 bug(bug 单要求见 skill `references/6-triage.md`)、对照门禁表 | 报告 + 放行建议 |

**第 6 步的放行决策是人工的,不能自动化、也不应假装能。** 自动化到「报告可信、证据齐全」为止。

## 版本差异用例的生成规则(REQ-VER-*)

版本新增 / 修改内容的用例,**只能从该版本需求文档派生**,每条需求子句至少一条用例,并带上 `req_refs` 指回需求。
**版本需求文档就位前,这一步不做** —— 没有需求就写不出合法期望,凭观察写出来的「期望」会把现有 bug 固化成期望。

拆解要点(完整规则见 skill `references/2-requirements.md` / `3-cases.md`):

- 一条需求拆成:正常路径 + 边界值;涉及货币、支付、结算、存档的**必须加边界、并发/重复、弱网中断**
- 期望必须可观测、可判定、自包含;含金额的写成精确值或明确公式,不写「合理增加」
- 一条期望里既有可机械判定部分又有主观部分,必须拆成两条

# 主题二:回归与冒烟

## 回归集构成

| 来源 | 判定模式 | 覆盖 | 构成用例 |
|---|---|---|---|
| 关键路径 | vision-closed / replay | 启动、登录、一局、结算、返回、商城、邮件 | INV-BOOT / CORE / LOGIN / UI |
| 数值与存档 | state-report | 货币、背包、存档、结算 | INV-COIN / BAG / SAVE / IDEM-C03 |
| 幂等与并发 | state-report + 故障注入 | 支付、发货、广告、分享、礼包码 | INV-IDEM-C01 / C02 / AD / SHARE / CODE |
| 弱网与更新 | state-report + 故障注入 | 断线重连、重试、更新中断 | INV-NET / PKG / VER-C02 |
| 配置交叉 | state-report | 配置数值在真机生效 | INV-CFG-C01 |
| 版本链路 | consistency / state-report | 更新、覆盖安装、版本号 | INV-VER-C01 / VER-C03 / INV-VER-C04 |
| 显示与美术 | vision-closed | UI 完整性、资源完整、像素回归 | INV-UI / NUM / ART-C01 / ART-C02 |
| 采集 | logcat / perf | 崩溃、ANR、启动耗时、内存 | INV-CRASH / PERF |
| 探索与回放 | explore / replay | 长尾缺陷;固化后的历史轨迹 | EXP-SYS-C01 与固化后的 EXP-* |
| 人工 | manual | 手感、美术质量、素材一致性 | INV-ART-C03 / INV-MKT-C01 |

**回放固化是把探索成果变成回归资产的机制:** 探索发现的问题复现后写成用例,历史上每次线上缺陷同样回流固化成用例,进下一轮回归集。**缺陷库只增不减是不允许的,每个线上缺陷都要变成一条永久回归用例。**

## 影响面选集矩阵(按变更挑必跑,控制回归时长)

| 变更模块 | 必跑用例(在冒烟之外追加) |
|---|---|
| 登录 / 账号 | INV-BOOT / LOGIN / SAVE / NET |
| 商城 / 支付 / 发货 | INV-COIN / IDEM-C01 / IDEM-C02 / BAG / INV-CFG-C01 |
| 战斗数值 / 结算 | INV-CORE / NUM / IDEM-C03 / INV-CFG-C01 |
| 背包 / 道具 / 邮件 | INV-BAG / UI / CODE |
| 网络 / 同步层 | INV-NET / LIFE / IDEM-C01..C03 |
| UI / 资源 / 美术改版 | INV-UI / ART-C01 / ART-C02 / NUM |
| 分包 / 加载 | INV-PKG / VER-C02 |
| 商业化(广告 / 分享 / 礼包码) | INV-AD / SHARE / CODE / IDEM 系列 |
| 存档结构变更 | INV-SAVE / VER-C01 + **全量** |
| 引擎 / SDK / 宿主升级 | **全量基线 + 机型矩阵**,不适用选集 |
| 影响面无法定位 | 默认 **全量** |

## 冒烟集(每个候选构建都跑,≈20 分钟)

冒烟集**不重复定义用例**,只定义「跑哪些、什么标准、多长时限」——用例正文在 `baseline-suite.md`,避免两处维护导致漂移。

| # | 用例 | 判定 | 通过标准 |
|---|---|---|---|
| 1 | INV-BOOT-C01 | vision-closed | 启动并进入主界面 |
| 2 | INV-CORE-C01 | vision-closed | 完成一局并结算返回 |
| 3 | INV-UI-C01(限额:商城 / 邮件 / 背包 3 屏) | vision-closed | 三屏无缺失、可返回 |
| 4 | INV-VER-C04 | consistency | 版本号与候选包一致 |
| 5 | INV-VER-C02 | vision-closed | 更新链路可完成(无更新时跳过并记录) |
| 6 | INV-CRASH-C01 | 采集 | 无 FATAL EXCEPTION、无 ANR、无闪退 |
| 7 | INV-PERF-C01 | 采集 | 启动耗时 ≤ 基线 120% |
| 8 | INV-NET-C01 | state-report | 断线重连后收敛(上报通道未就绪时降级为视觉判定:E1 与界面数值比对,并标注为弱判定) |
| 9 | INV-SAVE-C01 | state-report | 重启不回档(上报未就绪时降级:E1 视觉比对) |

**冒烟纪律:**

- 冒烟**不过不许进全量回归**;冒烟发现的 P0 直接停测转修复
- 冒烟执行率不足(如入口不可达)时,先修环境链路,不把环境问题记成产品问题
- 当前判定轮未实现,冒烟结论会停在 `pending_judgment`,**现阶段由人工看截图确认**(对应生命周期阶段的纵向切片校验);判定轮上线后自动判定

## 发版门禁(建议阈值,需团队确认后写死)

| 项 | 阈值 | 判定者 |
|---|---|---|
| 冒烟集 | 全绿 | 判定轮 / 人工 |
| P0 / P1 用例 | 全绿 | 代码 / 判定轮 |
| **实际执行率** | **≥90%**(不是通过率——执行率才代表真覆盖) | 报告 |
| 新增崩溃 | 0 | 采集 |
| 启动耗时 | ≤ 基线 120% | 采集 |
| skipped / blocked | 全部有明确原因记录 | 报告 |
| 放行决策 | **人工签署** | 人 |

## 版本验收单(每个版本的报告里带这一节)

- [ ] 变更清单与影响面判定完成(含「无法定位影响面」的变更列表)
- [ ] 版本差异用例(REQ-VER-*)已生成并**逐条复核通过**
- [ ] 冒烟集全绿
- [ ] 全量回归完成,实际执行率 ≥90%
- [ ] 无新增崩溃,启动耗时不退化
- [ ] 所有 skipped / blocked 有原因记录
- [ ] 报告含通过率与执行率双指标、缺陷单与证据可回溯
- [ ] 放行决策由人签署,附签署人与日期

# 版本级必跑用例(每次发版都跑,与版本内容无关)

# 用例: 覆盖安装后存档与设置保留

- **ID**: INV-VER-C01
- **来源**: invariant
- **角色**: 程序 / 策划
- **类型**: device-android
- **优先级**: P0
- **判定模式**: state-report

## 前置条件

- PRE-1: 旧版本账号金币 500、等级 12、背包 3 种道具,设置项(音效、画质)已截图记录
- PRE-2: 候选包已就绪

## 操作步骤

- S1: 不卸载旧版本,直接覆盖安装候选包并启动
- S2: 进入主界面,截图
- S3: 读取状态上报

## 期望结果

- E1: 覆盖安装后能进入主界面,不出现包含「登录失败」字样的弹窗
- E2: 上报的 player.coin 精确等于 500,player.level 精确等于 12
- E3: 上报的 inventory 仍为覆盖安装前的 3 种道具
- E4: 设置项取值与覆盖安装前一致

## 边界说明

- 小游戏没走安装器,等价操作为:旧版本进入 → 触发更新 → 更新完成后按同样断言校验

# 用例: 游戏内版本号与候选包一致

- **ID**: INV-VER-C04
- **来源**: consistency
- **角色**: 程序 / 市场
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 候选包的版本号与资源版本号已知(来自构建记录)

## 操作步骤

- S1: 启动候选包进入游戏
- S2: 打开含版本号显示的界面(首屏或设置页),截图

## 期望结果

- E1: 游戏内显示的版本号字符串与构建记录的包版本号一致
- E2: 版本号显示不出现「0.0.0」「unknown」「dev」任一占位值

## 源对

- **源对**: 构建元数据(包版本 / 资源版本)× 游戏内版本号显示

# 用例: 更新中断后可恢复,不白屏

- **ID**: INV-VER-C02
- **来源**: invariant
- **角色**: 程序
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 存在可触发的资源更新(用上一版本进入,或后台上传新的资源版本)
- PRE-2: 设备存储剩余空间充足

## 操作步骤

- S1: 启动游戏触发更新下载
- S2: 下载进行到约一半时断网 10 秒,截图
- S3: 恢复网络,等待更新完成
- S4: 进入游戏并进入一局对局

## 期望结果

- E1: 下载中断时出现包含「重试」字样的按钮或自动续传提示
- E2: 恢复网络后更新能继续完成并进入主界面
- E3: 进入对局后画面无占位块或棋盘格

# 用例: 更新后关键入口与系统完整

- **ID**: INV-VER-C03
- **来源**: invariant
- **角色**: 策划 / 程序
- **类型**: device-android
- **优先级**: P1
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 上一版本的关键入口清单已登记(商城、邮件、任务、活动、排行、设置等)
- PRE-2: 已更新到候选包并进入主界面

## 操作步骤

- S1: 逐个打开关键入口清单中的每个入口
- S2: 每个入口截图

## 期望结果

- E1: 每个入口元素都出现在主界面或一级导航中,不存在入口丢失
- E2: 每个入口都能打开并显示该系统的标志元素,不出现空白页
- E3: 不存在被置灰且点击无效的入口(有解锁条件的入口除外,解锁条件需在游戏理解文档登记)
