# 发布观测与决策流水线：把"现在能不能推"变成一条可核对的线

> 一个只读的发布观察器。盯住「提审 → 过审 → 单平台发布 → 24 小时观测 → 可以全量 / 可以全平台」这条线，把商店状态、按版本的报错率、AI 模拟玩家结果，汇总成状态页和一条钉钉私信。
> **它不点任何商店按钮。** 提审、放量、全量仍然由人在 App Store Connect / Play Console 里点；系统只负责看清、算清、说清。

## 问题

发布决策靠人拼信息：

- 商店状态在 App Store Connect / Play Console；
- 崩溃和内购失败在数数；
- 真机跑没跑、跑成什么样，在测试同学本地；
- "现在能不能放量"在负责人脑子里。

三个后果：

1. **放量靠感觉。** 没有一个按版本、按放出日切分的报错率基线。
2. **信息不同步。** 商店已过审，群里还在等；或者已经放量，测试还没开始看。
3. **出事说不清。** 崩溃率涨了，是新版本引入还是老问题，没有基线可对。

## 设计：九步，每一步都有数据来源

| 步骤 | 系统怎么知道 | 来源 |
|---|---|---|
| 1 线上提审 | iOS 版本状态变 `WAITING_FOR_REVIEW` / `IN_REVIEW`；Android 用命令录入 | 商店 API / 人工 |
| 2 过审 | `PENDING_DEVELOPER_RELEASE` / `READY_FOR_SALE` / `REJECTED` | 商店 API |
| 3 单平台发布 | 读分阶段发布状态与百分比；Android 人工录比例 | 商店 API / 人工 |
| 4 持续监控报错 | 每次 tick 采集；窗口=放出日到今天，基线=放出前 7 天的其它版本 | 数数 SQL |
| 5 AI 模拟玩家 | 三档：分层执行 / 视觉执行 / 盲跑；跑不了记 `blocked` | 模拟器 + adb |
| 6 分析报错率 | 崩溃、内购失败、资源下载、数据转换 + 新崩溃签名 | 规则引擎 |
| 7 钉钉汇报 | 私信；先落 `outbox/*.md`，发不出去也不丢 | 钉钉 |
| 8 提示可以全量/全平台 | 报告里**两个独立结论**，不合成一句 | 规则引擎 |
| 9 持续监控 | `watch` 常驻；全量后继续汇报 | 同上 |

### 关键设计：报错率要按版本、按放出日切

- **窗口**：从放出日开始，到今天。
- **基线**：放出前 7 天的**其它版本**，不是"这个版本的历史"。
- **新崩溃签名**：只出现于当前版本的崩溃，单独列出。

这样"涨了"才有对照：是当前版本引入的，还是大盘整体在涨。

### 关键设计：两个结论分开给

"可以全量"和"可以全平台"是两件事：

- 单平台放量后，崩溃率、内购失败率、新签名都达标 → 可以继续放量；
- 另一个平台还没发、或还没观测够 24 小时 → 不能全平台。

合成一句话会掩盖"另一个平台根本没数据"这种情况，所以报告里分成两条，各自带证据。

### 关键设计：只读，不代替人点按钮

- 提审、放量、全量都在商店后台人工操作。
- 系统只读状态、算指标、给建议。
- 每条建议都带数据窗口、基线、样本量；没有数据就写 `blocked`，不猜。

### 状态页与消息

- 状态页：版本、阶段、商店状态、放量比例、报错率 vs 基线、新崩溃签名、AI 模拟结果、一句"现在能不能推"。
- 钉钉私信：先落 `outbox/*.md`，再发；发送失败不丢内容，下次可重发。
- 阶段名沿用一套既有命名（`READY_TO_SUBMIT → IN_REVIEW → APPROVED → GRAY_RELEASE → OBSERVING → FULL_RELEASE`），不另造黑话。

## 结果

- 放量决策从"看群里消息"变成"看一条带基线的报告"。
- 出事时能立刻回答：这个崩溃是不是本版本新增、影响多少用户、基线是多少。
- 测试同学的 AI 模拟结果有了统一入口，跑没跑、跑成什么样一目了然。

## 边界

- 商店 API 的版本号/状态有时滞后，不能当实时真相；关键节点仍要人工核对。
- 数数的报错率依赖埋点和上报时机，新版本刚放出时样本量小，结论要标"样本不足"。
- AI 模拟玩家只能覆盖视觉和基础交互，不能替代真实支付、多指、帧级问题。
- 系统不点按钮，所以"已放量"以商店后台为准，状态页只做镜像。

## 如果重来

1. **先做"只读 + 状态页"，再做钉钉推送。** 推送太早会变成噪音，状态页先让人愿意看。
2. **基线口径要第一天写死。** 中途改口径，历史报告全部不可比。
3. **`blocked` 要显式。** 早期用空值表示"没跑"，看起来像"通过"；后来统一改成 `blocked` + 原因。
