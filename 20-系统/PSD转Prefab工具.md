# PSD → Prefab：让美术只画图，不标注

> 一个 AI 辅助的 UGUI prefab 生成工具。目标不是"全自动"，而是把美术的"按规则手工标注"降到接近零，同时让需求变更不再需要重发工具。

## 问题

原来的流程是：美术出 PSD → 按规则手工标注每个图层 → 程序/工具生成 prefab。三个痛点：

1. **标注全靠人。** 图层多、规则细，新人上手慢，错一个名字就返工。
2. **需求一变就重发工具。** 工具更新要美术重新安装/替换，成本高，导致大家不愿意更新。
3. **直接上 VLM 不通。** 试过"扁平效果图 + 散图"的方案：像素模板匹配对通用形状区分力差，一个通用底板能"通吃"所有区域；VLM 能框区域、能描述内容，但不擅长给像素坐标，也不知道散图文件名。

## 关键洞察：PSD 里已经有大部分答案

| 之前要还原的东西 | PSD 里的状态 |
|---|---|
| 每张散图的位置/尺寸 | 图层 bounds 直接给 |
| 层级/分组 | 图层组结构直接给 |
| 该贴哪张散图 | 每个图层本身就是那张图，不需要匹配 |
| 文字内容/样式 | 文字图层自带 |

于是"需要智能"的部分只剩三件：**给图层起规范名、判组件类型、推断分组**。这三件正好是 VLM 的强项，而且不需要像素坐标——之前的死穴全部消失。

## 架构：三块 + 一份契约

```
① 美术拆图工具(exe)  →  ② 中间数据(散图 + prefab.json)  →  ③ Unity 建 prefab
   本地·局部知识            交接契约·版本化稳定                Unity 内·全局知识
```

### 知识归属原则

| 模块 | 掌握的知识 | 面向谁 |
|---|---|---|
| ① 拆图工具 | 仅本 PSD 的局部知识 | 美术（只有 PS） |
| ② 中间数据 | 两端唯一的协调契约 | 机器 |
| ③ Unity 建 prefab | 全项目的全局知识 | 程序（有仓库） |

- 公共图去重需要全局知识 → 必须放 ③（Unity 反查）。
- 切图只需要局部知识 → 放 ①。
- 两者靠 ② 解耦，各自独立演进。

三条反模式（用来守边界）：

- ① 不判全局公共、不建 prefab、不依赖 Unity 仓库。
- ③ 不重切 PSD、不要求装 PS。
- ② 必须自包含：③ 只看 ② 就够。

## 部署：不打单 exe

这是整个方案里最容易被忽略、但决定能不能长期维护的一步。

**反例：PyInstaller 打成单 exe。** 每次更新都要提交 80–150MB 二进制，仓库历史很快爆炸。

**采用方案：运行时提一次 + 逻辑用源码。**

```
svn/
├── runtime/python-embed/   # 内嵌 Python + 依赖，提交一次，极少变
├── tool/                   # 工具源码（.py/.html/.js/.css），更新=小 diff
├── config/                 # rules.json / 组件注册表，改了即生效
└── 启动.bat
```

- 日常更新只改 `tool/` 或 `config/`，美术 `svn update` 秒完。
- 内嵌 Python 运行时，美术不需要装 Python。
- WebView2 缺失时随包带 Evergreen 安装器，一次性装好。

对美术的硬要求只有一条：**整个文件夹双击即用，不需要管理员权限、不需要装依赖。**

## 抽图里的几个硬决策

### 1. 非文字层禁用实时图层样式

非文字图层如果带阴影/描边/发光，导出时检测到启用的图层样式就报红，要求美术栅格化进像素。原因：psd-tools 对复杂图层样式的渲染不可靠，宁可让美术在 PS 里确认一次，也不要在导出后出现"看起来差不多但位置/边缘不对"。

### 2. 文字层的样式当数据记，不当像素

文字层的描边、阴影、字距、行距记进 `text` 块，由 Unity 端映射到 TMP/UGUI。这样文字保持可编辑、清晰，不依赖 PSD 渲染。

### 3. trim 必须同步更新 rect

按 alpha 包围盒裁紧致图，同时把画布内偏移写进 `node.rect`。任何 trim 都要同步更新 rect——这是"位置不偏"的唯一保证。

### 4. AI 只做建议，不自动落库

命名和组件类型可以由 VLM 给建议，但预览页必须让美术逐个确认；公共图误配要能当场否决。AI 不直接写最终结果。

## 结果

- 美术从"逐图层标注"变成"拖入 PSD → 检查建议 → 导出"。
- 需求变更只更新 `tool/` 或 `config/` 的文本 diff，不再重发安装包。
- 中间契约稳定，Unity 端可以独立演进。

## 如果重来

1. **先定契约，再写工具。** 第一版工具和 Unity 端同时改，契约来回变，返工最多。
2. **"非文字层禁用图层样式"应该更早写死。** 这是后面所有抽图稳定性的前提。
3. **不要试图让 VLM 给坐标。** 试过一次，坐标不可用；PSD 的 bounds 才是可靠来源。
