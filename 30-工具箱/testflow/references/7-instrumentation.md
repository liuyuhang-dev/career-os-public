# 7 · 游戏内状态上报(增量项)

**这是增量项,不是前置条件。** 没有它这套流程也能跑;它的作用是**把判定从"看画面"升级到"读状态"**,专门解决视觉判不了的那一类缺陷。

需要客户端同学配合,所以这份文档是给他们的接口约定。

## 为什么需要它

视觉判定能看到的一切都是**显示层**。有一类缺陷的特征是**"看起来是对的"**:

- 存档跨端/跨设备不一致
- 结算精确性(界面显示 100,实际存了 99.9999)
- 离线操作重放导致双倍结算
- 重复上报幂等失效
- 断线重连后状态回退但界面刷新成了正确值
- 大数精度丢失(界面四舍五入,内部已经溢出)

这类缺陷只靠截图永远发现不了。**这是唯一必须客户端配合才能覆盖的一类。**

## 触发:测试模式开关

用官方提供的环境标识,**不要自己发明开关**:

| 环境 | 标识 |
|---|---|
| 微信小游戏云测 | `GameGlobal.isTest === true` |
| 微信小游戏开发/体验版 | `wx.getAccountInfoSync().miniProgram.envVersion` 为 `develop` / `trial` |
| 抖音小游戏 | 无官方测试标识,用自建开关(见下) |

抖音侧无官方标识,建议用**构建期变量**而非运行时配置:测试构建注入 `__TESTFLOW__` 全局标记,正式包中该代码路径被裁剪。

**测试模式必须是构建期可裁剪的**,不能依赖运行时开关——否则有被利用的风险。

## 上报通道:走 HTTP,不走日志

**这是关键设计决策。**

| 方案 | 问题 |
|---|---|
| 打 console log | 微信小游戏真机拿不到 console;iOS 平台完全没有 logcat |
| 写本地文件 | 小游戏沙箱没有通用文件写入接口 |
| **HTTP POST 到采集端** | **跨平台通用(微信/抖音/iOS/Android 都一样),落盘可控,结构化** |

小游戏环境有 `wx.request` / `tt.request`,这是最可靠的通道。

```js
// 仅测试构建存在
__TESTFLOW__.report({
  runId: "run-20260917-142033",
  caseId: "REQ-003-C01",
  step: "S2",
  at: Date.now(),
  state: {
    "player.coin": 500,
    "player.coinDelta": 40,
    "player.killCount": 8,
    "player.level": 12
  }
});
```

采集端就是一个本地 HTTP 服务(执行器起),把 payload 落到 `04-runs/evidence/<caseId>_state.json`。

## 建议暴露的状态字段

不必暴露全量状态,只暴露**能被断言**的关键量。建议分四组:

| 组 | 字段示例 | 支撑的断言 |
|---|---|---|
| 货币与资源 | `player.coin`、`player.gem`、`player.energy` | 不变量:不为负、不超上限、结算精确 |
| 进度与背包 | `player.level`、`player.exp`、`inventory[].{id,count}` | 不变量:不超上限、无重复条目、不丢档 |
| 回放与幂等 | `pendingOps[]`、`lastOpId`、`appliedOpIds[]` | 弱网:重放不双倍、上报幂等 |
| 会话与连接 | `session.state`、`session.reconnects`、`sync.lastSyncAt` | 弱网:重连收敛、状态不回退 |

**回放与幂等这一组对弱网游戏最关键**,也是外部手段完全无法观测的。

## 确定性开关(让断言不抖)

判定内部状态要求可复现,提供三个开关:

```js
__TESTFLOW__.setup({
  seed: 20260917,           // 固定随机种子:随机掉落、暴击、匹配
  fixedTimestepMs: 16,      // 固定逻辑帧步长
  disableAnimations: true,  // 关闭动画与特效,消除时序抖动
  mockNetwork: {            // 网络层可注入,用于构造确定性弱网场景
    latencyMs: 0, lossRate: 0.0, disconnectAfterMs: null
  }
});
```

**`mockNetwork` 是弱网收敛断言的前提。** 若网络层是硬编码单例,先做可测性改造——这是前置工程,需要评估成本。

## 收敛断言的语义

`assert_convergence: true` 要求游戏在上报里给出**收敛完成信号**,否则"重连后状态一致"无法判定(你不知道什么时候算重连完成):

```js
// 重连并完成同步后上报
__TESTFLOW__.report({
  caseId: "INV-NET-C02", step: "converged",
  state: { "session.state": "connected", "sync.lastSyncAt": 1758091200000,
           "player.coin": 500, "pendingOps": [] }
});
```

断言方能成立:`session.state == "connected"` 且 `pendingOps` 为空 且关键数值与断线前一致。

**没有这个信号,弱网用例只能判"界面看起来正常",那正是视觉判定的老问题。**

## 输入注入(可选,解决多指限制)

`adb shell input tap` 无法真正多指同时操作。若要自动化这类用例,可在测试构建里提供输入注入:

```js
__TESTFLOW__.injectInput({
  type: "touch", pointers: [
    { id: 0, x: 0.2, y: 0.8, phase: "move" },   // 摇杆
    { id: 1, x: 0.8, y: 0.3, phase: "down" }     // 瞄准
  ]
});
```

座标同样用归一化。**这条是可选增强**,优先级低于状态上报。

## 接入成本评估清单(给客户端同学)

- [ ] 网络层是否可注入?若是硬编码单例,改动面多大?
- [ ] 随机数是否都走统一入口(能否一处固定种子)?
- [ ] 逻辑帧是否有固定步长机制?
- [ ] 关键数值是否有统一的状态读取入口(还是要散点插桩)?
- [ ] 构建期裁剪是否可行(正式包不能含上报代码)?
- [ ] **小游戏 WebGL 环境内能否发起 HTTP**(理论上 `wx.request` 可以,需实测)

## 未验证的部分

**小游戏环境内自注入通道的可行性尚未验证。** 小游戏是 WebGL/wasm 跑在无 DOM/BOM 的 JS VM 里,AltTester/Gamium 这类现成方案依赖原生 socket,**很可能不可用**,只适用于原生构建与编辑器。

上面这套(`GameGlobal` 暴露 + HTTP 上报)是理论可行路径,**但没有官方文档背书,需要在真机上实测确认**。在确认之前,不要把它当作已解决的依赖。

## 优先级

| 优先级 | 项目 | 理由 |
|---|---|---|
| 高 | HTTP 状态上报 | 跨平台通用,解决视觉判不了的一类缺陷 |
| 高 | 固定随机种子 | 成本低,直接消除抖动 |
| 中 | 网络层可注入 | 弱网收敛断言的前提,但改动面可能大 |
| 低 | 输入注入 | 只服务多指用例,数量少 |
