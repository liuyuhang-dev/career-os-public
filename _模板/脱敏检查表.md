# 脱敏检查表

> 每个文件进库前过一遍。**原则：能证明能力，但不能让雇主难做。**

## 必删

- [ ] 公司全称、品牌名、项目代号（改「某休闲游戏项目」「某 AI 研发项目」）
- [ ] 内网域名与 IP（`gitlab.xxx.com`、`10.x.x.x`、`192.168.x.x`）
- [ ] 端口与内部服务名（`12xxx`、`某内部服务名`）
- [ ] 真实人名（同事、外包、供应商）
- [ ] AppID / Client ID / corpId / userId / 群 ID
- [ ] 任何形式的密钥：API Key、token、密码、keystore 口令
- [ ] 需求文档原文（要写就写"我们怎么拆需求"，不写需求内容）
- [ ] 用户数据：ID、分群、埋点明细、留存/付费原始数字

## 可保留

- [x] 工作方法的步骤与原则
- [x] 架构图、流程图、表结构（去掉字段名中的业务专名）
- [x] 量级数字（"100+ 任务""700+ 节点"——只要不构成商业情报）
- [x] 通用技术名（Unity、Git、SVN、SQLite、钉钉、GitLab）
- [x] 你自己写的代码（前提是不含公司业务逻辑）

## 三问自查

1. **这段话如果被雇主看到，会让我难做吗？**
2. **这段话如果被面试官追问细节，我能不靠内部资料讲清吗？**
3. **删掉这句，我的能力还成立吗？**（成立就删）

## 常见漏网

| 位置 | 容易漏什么 |
|---|---|
| 代码注释 | 内网地址、TODO 里的真名 |
| 配置示例 | 真实 AppKey 前几位 |
| 截图 | 工单号、头像、右上角账号名 |
| Git 提交信息 | 公司邮箱、issue 编号 |
| 文档元数据 | docx/xlsx 的作者、公司属性（导出前清） |
