## 二、🔴 疑似真实问题（请优先人工验收）

### 问题1：连胜升级无"首次通关"校验（⚠ 2026-08-29 前提澄清，降级为"暂不构成漏洞"）

> **澄清**: 开发侧确认**关卡为递进式设计、不允许回退、一关只能打一次**。
> 原攻击路径（回打旧关卡重复刷连胜）在正常游玩中**不存在** → 每次胜利天然即首次通关，
> 实现「胜即连胜+1」与递进设计**自洽**，暂不构成可利用漏洞。
>
> **状态**: ✅ 验收结论 = 实现与设计一致（前提：客户端确实封死已通关卡的重复进入，见下）。
> **遗留 2 项**:
> 1. 客户端侧：已通关卡的入口/按钮是否置灰不可进——若可再进则漏洞复活，升回 P0（验收步骤见手工文档 A-1 修订版）。
> 2. 服务端侧：关卡结果请求需校验关卡首通（防伪造请求绕过递进规则），对应 TR-SCORE-024 / TR-SEC-004，超客户端测试范围，转服务端。
> **用例回流**: TR-SCORE-019、TR-STREAK-009 前提不成立 → 建议删除或改写为"中途退出后重进未通关关卡"口径（回流策划）。

- ~~原验证步骤~~（已作废——原步骤基于"可回打旧关卡"的错误假设，修订版见手工执行文档「A-1」）

- **对应用例**: TR-SCORE-019 / TR-SCORE-020 / TR-STREAK-009
- **用例预期**: 连胜仅由**首次通关**推进；重复通关已通过关卡，连胜次数和倍率不应提升
- **实现现状**（代码证据）: `ActRanking.OnGameSuccess` 调 `AddScore(multiplier, !lastFailed)`，连胜是否推进**只看上一局是否失败**，全程无任何"本关卡是否首次通关"的判定
- **业务风险**: 玩家可以反复打最低难度已通关卡，安稳把连胜倍率刷到 x20，积分活动被刷穿
- **🧪 人工验收步骤（游戏内约 5 分钟）**:
  1. 进入活动期，先正常通关一个**新关卡**（第 1 次打），打开排行榜记住当前"连胜次数/倍率档位"（例如 x1 → 下一局预告 x3）
  2. 选一个**早就通关过的旧关卡**，连续通关 2 次
  3. 每次通关后回到排行榜/进关面板查看倍率预告
  4. **预期（用例口径）**: 打旧关卡连胜不涨、倍率档位不动
  5. **若实测连胜+1、倍率档位升档 → 问题成立**，录屏留证

### 问题2：追分机器人目标分比例区间超出用例上限

- **对应用例**: TR-BOT-005
- **用例预期**: 追分机器人目标分 = 玩家分 × [**1.05, 1.15**] 随机
- **实现现状**（配置证据: `followrobot` 表）: 实际两档配置为 **1.2~1.3** 与 1.05~1.1。其中 1.2~1.3 完全高于用例上限 1.15
- **业务风险**: 追分机器人被拉得太高，玩家升到第一名前后分差被放大 20%~30%，追分压迫感超策划预期（或用例文档滞后于配置改版）
- **🧪 人工验收步骤（游戏内，配合 GM 命令约 10 分钟）**:
  1. 用 GM `syncranking` 记录当前机器人分数；用 `setuserscore` 把自己分数设到一个明显值（如 1000）
  2. 反复触发排名称前条件，等追分机器人开始追分
  3. 观察追分机器人**最终停在的分数**，计算 比例 = 机器人最终分 ÷ 1000
  4. **预期（用例口径）**: 比例落在 1.05~1.15
  5. **若实测比例达到 1.2~1.3 → 配置与用例口径不一致**，找策划确认是"配置改了文档没更"还是"配置配错"（注意：若策划说现在是 1.2~1.3，则这条是用例文档过期，改文档即可）

### 问题3：同分排名规则与用例口径相反

- **对应用例**: TR-RANK-008 / TR-RANK-009
- **用例预期**: 总分相同时，按"达到该分数的时间早者在前，完全相同按**用户ID升序**"（玩家 id=0 → 同分组第一）
- **实现现状**（代码证据: `RankingUserSorter.Compare`）: 同分按 **ID 降序**——机器人永远压玩家，玩家在同分组垫底；**且排序器完全没有"达分时间"维度**
- **业务风险**: 结算名次奖金按逻辑名次发，同分场景玩家权益受损；若两名真人玩家同分，判定也只看 ID，无时间先手
- **🧪 人工验收步骤（游戏内约 8 分钟）**:
  1. 活动期内用 GM `setuserscore` 把自己分数设成与某个机器人**完全相同**（先用 `syncranking` 查机器人分数）
  2. 打开排行榜看自己与该机器人的先后
  3. **预期（用例口径）**: 玩家（id=0，ID 升序最小）应排同分组**第一**
  4. **若实测机器人排在玩家前面 → 实现与用例口径相反**，截图留证，找策划裁决到底按哪套规则（裁决前不能算实现 bug，裁决后按裁决结果定）
