# 把文字写得不像机器写的

> 2026-11 改简历时总结的。适用于简历、汇报、对外文章——凡是"别人一眼要判断你这个人"的场合。

## 一、什么是"人机感"

不是用词高级，也不是排比多。是四个很具体的特征：

| 特征 | 表现 | 为什么读着假 |
|---|---|---|
| **句式统一** | 每条都是「名词：A、B、C」 | 人不会每句话一个模子 |
| **动词单一** | 搭建、建立、维护、负责、主导 | 这些是"职责词"，不是"动作" |
| **自造名词** | "可复现基线四件套""五段链" | 读者得先解码，解码完发现没必要 |
| **没有一件具体的事** | 全是体系、机制、能力 | 看不到这个人干过什么 |

一句话：**读起来像在描述"一个岗位"，不像在描述"一个人"。**

## 二、四类改法

### 1. 打散句式

不要每条都用冒号加分号。一半写成完整句子，长短交替。

> ❌ 质量体系：需求前置规则 → 提测前静态交叉 → 冒烟／回归／版本专项 → 发版门禁
> ✅ 质量把关：测试不是起点。需求评审先拦掉判不清的需求，出包前用脚本扫配置表，提测后按冒烟、回归、版本三轮走。

后者多了"测试不是起点"这句判断——**判断是人写的，流程是模板写的。**

### 2. 换动词：从"职责词"换成"动作词"

| 别用 | 换成 |
|---|---|
| 搭建 / 建立 / 构建 | 挪、拦、扫、拆、合并、砍掉 |
| 维护 / 负责 | 盯着、每天看、出问题先找我 |
| 推动 / 落地 | 说服、逼着改、拖进流程里 |
| 优化 / 提升 | 从 X 变成 Y（有前后对比） |

> ❌ 写了个交付助手：拖入即提交、断网重试、同名冲突保护、工单号回填
> ✅ 写了个交付助手：美术把文件拖进文件夹就算交了。名字不合规自动退回并说明原因，重名自动编版本号，断网会重试。

第二版有画面：**有人把文件拖进去，然后出错被退回。** 第一版只有功能列表。

### 3. 删掉自造的名词

凡是需要解释一遍才懂的名词，都删掉。

> ❌ 可复现基线四件套
> ✅ 代码版本、安装包指纹、配置快照、页面清单——换个人换台机器，结论一样

**"四件套"三个字省了 20 个字，但增加了读者的一次解码成本。** 不划算。

### 4. 加一点口语连接

不是加"我觉得""其实"，是加**人和人说话时会用的连接**：

- "都在我这边"
- "大概三类"
- "人不点确认就不落库"
- "给不出就是漏测"

这些词在正式文档里会被删，但在简历里是**可信度信号**——它说明写的人真的干过，不是套模板。

## 三、自查清单（写完读一遍，逐条问）

1. **有没有连续三条是同一个句式？** 有就改一条。
2. **动词有没有重复？** 三个"搭建"里至少换一个。
3. **有没有需要解释才懂的词？** 有就换成大白话。
4. **能不能想象自己说出口？** 说不出口的那句，重写。
5. **删掉这句，信息少了吗？** 没少就删。

## 四、边界：别过头

- **技能栏适合清单**。那不是叙事，是索引，不需要人味。
- **简历不能变成聊天**。"我觉得挺有意思"这种话不该出现。
- **口语连接最多三处**。多了像在套近乎。

一句话原则：

> **结构可以模板化，句子不能。**
