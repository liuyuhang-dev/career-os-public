# 通用基础测试用例集(基线集)

**这套用例回答两个问题:**

1. **主题一:我们的游戏怎么测、需要跑哪些内容?** —— 见「怎么测:六个层」与「执行编排」。
2. **主题二:如何覆盖美术、策划、程序开发、市场?** —— 见「角色覆盖矩阵」。

**定位:这是每个版本都要复用的通用基线,不依赖任何版本需求文档。** 全部期望来自通用正确性不变量与源间一致性(见 skill 的 `references/3-cases.md`),也不需要真机之外的材料就能成立。
**版本新增内容的验收用例、回归编排与发版门禁见同目录 `version-suite.md`。**

---

## 三个规矩(违反任何一条,结果不可信)

1. **玩与判分离。** 执行者只输出截图与原始观测值,不输出「通过/失败」;判定由代码(封闭断言、回放比对)或独立的一轮判定完成。
2. **期望不能来自观察。** 本文件所有期望来自不变量或源间一致性,没有一条是「看屏幕上现在是多少就写多少」。发现与期望不符时先回到来源确认,不许把现有行为写成期望。
3. **没证据不许判通过。** 证据没采到 → `blocked`;能力未实现 → `skipped: executor not implemented`。**绝不伪装成 pass。**

## 怎么测:六个层,每个层只承诺它判得了的东西

| 层 | 测什么 | 判定方式 | 现在能不能跑 | 本集用例 |
|---|---|---|---|---|
| L1 静态交叉(出包前,零设备) | 配置表自洽:悬空引用、主键重复、枚举越界、字段缺失 | 机械脚本 | 配置表接入即可跑 | 见下方「出包前静态检查清单」(暂不写成用例) |
| L3-a 显示层 | 关键路径、UI 完整性、资源缺失、文案 | `vision-closed` 封闭视觉断言 | 判定轮未实现 → 停在 `pending_judgment`,截图照常采 | BOOT / CORE / UI / NUM / ART-C01 / PKG 等 |
| L3-b 内部一致性 | 货币、背包、存档、结算、幂等、弱网收敛 | `state-report`(需客户端状态上报) | 上报通道未启动 → `blocked` | COIN / BAG / SAVE / IDEM / NET 等 |
| 采集 | 崩溃 / ANR、启动耗时、FPS、内存 | 机械比对(logcat / perf 字段) | 崩溃与性能采集未实现 → `blocked` | CRASH / PERF |
| 探索 | 长尾缺陷:流程断裂、卡死、异常弹窗 | `explore`,**不判通过/失败,只报异常候选** | 探索调度未实现,先人工 + 半自动 | EXP-SYS-C01 |
| 人工 | 手感、美术质量、品牌一致性、难度曲线 | `manual`,`pending_manual` | 可跑 | ART-C03 / INV-MKT-C01 |

**这张表就是「跑哪些内容」的答案:能自动的交给对应判定模式,判不了的明确标人工,能力缺失的显式 `blocked`,不拿视觉假装覆盖内部一致性。**

## 执行编排(什么时机跑什么)

| 时机 | 跑什么 | 时长量级 | 准出 |
|---|---|---|---|
| 每个候选构建 | **冒烟集**(清单见 `version-suite.md`) | ≈20 分钟 | 全绿才允许进全量回归 |
| 每个发版 | **全量基线(本集)+ 版本差异用例** | 1–2 小时 | 见 `version-suite.md` 门禁表 |
| 引擎 / SDK / 宿主升级 | 全量基线 **× 机型矩阵**(INV-DEVICE-C01) | 按矩阵规模 | 无崩溃、无 P0 |
| 持续(上线后) | 探索(EXP-SYS-C01)+ 线上反馈回流固化 | 长时 | 发现率与误报率达标 |

## 环境与前置(每轮开跑前逐项确认)

- 测试账号与测试商品固定(虚拟支付/测试商品,不依赖真实支付链路)
- 固定入口可用(宿主「最近使用」列表或开发版扫码,入口探针先验证)
- 状态上报通道就绪(客户端接入后,弱网/幂等类用例才有判定依据)
- 每台设备建立坐标档案(归一化坐标 + 安全区),截图尺寸与窗口映射记录进运行元数据
- 性能基线已采集一次(首版人工采,之后自动比对)

## 角色覆盖矩阵(主题二的核心答案)

| 角色 | 他们最怕的缺陷 | 覆盖用例 | 判定方式 | 只能人工的部分 |
|---|---|---|---|---|
| **美术** | 资源缺失、贴图错乱、文字截断、改版把画面改坏 | INV-ART-C01 / INV-ART-C02 / INV-UI-C01 | 视觉封闭断言 + 像素回归(带遮罩阈值) | 画面质量、风格统一、品牌元素一致性(INV-ART-C03) |
| **策划** | 数值显示错误、配置没生效、文案错、需求做偏 | INV-NUM-C01 / INV-CFG-C01 / INV-COIN-C01 / INV-BAG-C01 / INV-CORE-C01 | 视觉封闭断言 + 配置 × 运行时交叉 | 难度曲线、趣味性、引导体验;需求一致性用例在拿到需求文档后由流水线生成(REQ-*) |
| **程序开发** | 崩溃、卡死、内存泄漏、弱网失效、丢档、重复入账 | INV-CRASH-C01 / INV-PERF-C01 / INV-NET-C01 / INV-LIFE-C01 / INV-SAVE-C01 / INV-IDEM-C01..C03 | 采集 + 状态上报 + 故障注入 | 崩溃根因定位(采到栈,定位到代码要研发);静态幂等扫描见工具 `scan_idempotency.py` |
| **市场** | 买量素材与游戏不符、分享/广告奖励出错、包体加载失败、礼包码被薅 | INV-MKT-C01 / INV-AD-C01 / INV-SHARE-C01 / INV-CODE-C01 / INV-PKG-C01 | 源间核对(人工)+ 幂等断言 | 素材与落地页承诺的逐条核对;真实支付链路无法自动化,登记为人工 |

> 四个角色不是四套独立测试,而是**同一条流水线上的四种视角**:美术对应显示层与像素回归,策划对应数值与配置交叉,程序对应采集与内部一致性,市场对应商业化链路与外部承诺一致性。人工不是被移除,而是被收敛到「只能人工」的清单里,其余全部自动化。

## 出包前静态检查清单(L1,零设备依赖,先于一切真机)

这类检查应该做成脚本而不是用例文件(见 skill `references/10-upstreams.md`)。项目提供配置表后逐项落地:

- [ ] 悬空引用:道具表引用的图标不存在、关卡表引用的怪 id 不在怪物表、商店表引用的道具 id 不存在
- [ ] 主键重复:同 id 两行
- [ ] 字段缺失 / 空值:必填列为空
- [ ] 类型与范围:数值列出现非数字、负数、超出字段说明范围
- [ ] 枚举越界:类型字段的值不在合法枚举内
- [ ] 表间一致性:两张表对同一实体描述不同
- [ ] 孤立行:配置了但没有任何引用(可能废弃,也可能漏接)

# 用例: 启动并进入游戏主界面

- **ID**: INV-BOOT-C01
- **来源**: invariant
- **角色**: 程序 / 策划
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 设备已安装宿主(微信 / 抖音)并完成登录,游戏入口可达
- PRE-2: 网络连通,无待下载的版本更新

## 操作步骤

- S1: 启动宿主,从入口打开游戏
- S2: 等待进入主界面(最长等待 60 秒)
- S3: 截图记录主界面

## 期望结果

- E1: 画面出现主界面标志元素 —— 含「开始游戏」字样的按钮或等价的入口按钮(元素名称以游戏理解文档登记的词汇表为准)
- E2: 画面不是整屏纯色(排除白屏、黑屏)
- E3: 60 秒内完成进入,未停留在启动画面

# 用例: 完成一局完整对局并结算返回主界面

- **ID**: INV-CORE-C01
- **来源**: invariant
- **角色**: 策划 / 程序
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 账号处于可自由开局状态(新手引导已完成或可跳过),体力 / 门票足够开始一局

## 操作步骤

- S1: 在主界面点击「开始游戏」
- S2: 完成一局(按游戏理解文档登记的结束条件让对局结束)
- S3: 在结算页截图,然后点击返回
- S4: 截图记录返回后的画面

## 期望结果

- E1: 对局到达结束条件后进入结算页,结算页出现含「结算」字样的标题或按钮
- E2: 结算页不出现「NaN」「Infinity」「undefined」「null」任一文本
- E3: 从结算页返回后,主界面标志元素再次出现

# 用例: 无登录态首启可玩,重启后登录态稳定

- **ID**: INV-LOGIN-C01
- **来源**: invariant
- **角色**: 程序 / 市场
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 新设备,或已清除游戏数据(无登录态)

## 操作步骤

- S1: 冷启动进入游戏,不进行任何登录操作
- S2: 尝试完成一次开局
- S3: 杀掉游戏进程,重新启动并进入

## 期望结果

- E1: 未登录状态下可进入主界面,并可完成一次开局
- E2: 重启后仍可进入主界面,不出现包含「登录失败」「网络错误」字样的弹窗
- E3: 账号入口可打开,打开后不出现报错弹窗

# 用例: 系统界面遍历:UI 完整性与返回路径

- **ID**: INV-UI-C01
- **来源**: invariant
- **角色**: 美术 / 策划
- **类型**: device-android
- **优先级**: P1
- **判定模式**: vision-closed

## 前置条件

- PRE-1: 已进入主界面;界面清单以游戏理解文档登记为准(如商城、背包、邮件、任务、设置、排行榜)

## 操作步骤

- S1: 从主界面依次打开界面清单中的每一个界面,每个界面截图
- S2: 对每个界面检查文字截断、按钮重叠、元素溢出容器边缘
- S3: 从每个界面执行返回操作

## 期望结果

- E1: 每个界面截图中不存在被截断的文字(末尾省略号「…」与长文本滚动区除外)
- E2: 每个界面中按钮与按钮、按钮与相邻文字之间无重叠
- E3: 每个界面都能返回上一层,返回后上一层标志元素出现

# 用例: 运行全程无崩溃、ANR 与闪退

- **ID**: INV-CRASH-C01
- **来源**: invariant
- **角色**: 程序
- **类型**: device-android
- **优先级**: P0
- **判定模式**: vision-closed

## 前置条件

- PRE-1: adb 已连接设备,logcat 已清空

## 操作步骤

- S1: 从启动开始至本轮用例全部执行结束,持续采集 logcat
- S2: 每步截图,检测画面是否退回宿主界面或系统桌面

## 期望结果

- E1: logcat 中不出现包含「FATAL EXCEPTION」的行
- E2: logcat 中不出现包含「ANR in」的行
- E3: 任一步骤后画面未退回宿主界面或系统桌面

## 判定方式

- 机械采集断言:对 logcat 与截图做确定性比对,不经视觉模型
- 崩溃检测能力未实现前,本用例返回 blocked,不得记 pass

## 采集要求

- evidence: logcat / screenshot

- **判定模式**: vision-closed

- 机械采集断言:对 perf 数据做数值比对,不经视觉模型
- 性能采集能力未实现前,本用例返回 blocked,不得记 pass

## 采集要求

- evidence: perf

- **来源**: invariant
- **角色**: 程序 / 策划
- **类型**: device-android
- **优先级**: P0
- **判定模式**: state-report
