# 系统 case 模板

> 每个 20-系统/ 文件都用这个结构。目标：让没在场的人 5 分钟看懂"你为什么这么设计"。

## 一句话

（这个系统解决了谁的什么问题，一句话。不许用"提升效率""赋能"这类词。）

## 背景与约束

| 项 | 内容 |
|---|---|
| 当时的状态 | （没有这个系统时，事情是怎么烂的） |
| 规模 | （人数 / 任务数 / 频次 / 数据量） |
| 硬约束 | （时间、人力、不能改的东西、政治因素） |
| 我的角色 | （设计 / 实现 / 推动，边界要说清） |

## 设计

（一张结构图或流程，配 3–5 条设计原则。原则要能反驳——"为什么不那样做"。）

## 落地过程

（按周或按阶段。每一步写"遇到什么阻力 → 怎么解决"。阻力比结果有说服力。）

## 结果

（可核验的数字；没有数字就写可观察的变化。区分"我做的"和"团队做的"。）

## 如果重来

（一个真做错的地方 + 现在的做法。）

## 可复用件

（这套东西里，哪部分能搬到别的场景？）
