## 二、平台维度 P1–P15

当被测对象本身是一个平台（外壳 / 插件 / 数据层 / 集成）时，功能维度不够用，需要叠加这一组。

| id | title | 判定口径 |
| --- | --- | --- |
| P1 | 入口注册与外壳可达 | 侧栏入口、主路由、注册接口三处必须一致；新增模块后自动出现在注册接口与侧栏，选中态跟随 URL。判定：全部入口可打开、无白屏、无 404，数量一致。 |
| P2 | 深链与视图状态可恢复 | 主路由可直开；tab、筛选、分页等用户视为「位置」的状态必须进 URL 或持久化。判定：刷新/后退/前进后回到同一视图。 |
| P3 | 启动就绪与健康检查 | 服务在全部模块注册完成前不得宣称可用；健康口径要覆盖「注册 + 数据源扫描完成」，不能只看端口。判定：重启瞬间注册接口也返回全量。 |
| P4 | 数据源绑定与路径可移植 | 文件存在即必须被识别；覆盖路径分隔符、中文/弯引号目录、CRLF/BOM、大小写敏感。判定：报「文件缺失」前先核对文件真实存在。 |
| P5 | 空数据与部分失败隔离 | 空表、空目录、坏行只影响自身；消费方跳过或建空结构并说明哪一项为空。判定：一条坏数据不得让同目录其他功能整体不可用。 |
| P6 | 错误呈现与可诊断 | 错误必须落到 UI，包含「哪个对象/字段/行 + 哪一步失败 + 可重试」，不得只给裸堆栈。判定：非开发人员能据此定位。 |
| P7 | 文件落盘完整性 | 保存后列顺序、引号转义、换行、BOM 不被破坏；只读、被占用、磁盘满要显式失败。判定：保存后重新解析内容等价。 |
| P8 | 并发与多实例 | 两个窗口或两人同时改同一对象时冲突必须可见；共享偏好与共享库要一致。判定：不静默覆盖，最后写入可追溯。 |
| P9 | 权限与网络边界 | 谁可读/写/删必须明确；无鉴权时只能绑本机，或明示「同网即可读写」的信任边界。判定：未授权写被拒绝，路径穿越被拒绝。 |
| P10 | 规模与性能 | 明确首屏/搜索/保存阈值，并在 10x 数据下复测；超阈值要有加载态而不是假死。判定：给出可接受上限，而不是「目前还行」。 |
| P11 | 外部依赖降级 | AI、通知、数据平台等外部依赖不可用或超时时，界面要说明「哪一项不可用、本地功能仍可用」。判定：外部失败不阻塞本地编辑。 |
| P12 | 跨模块对账 | 同源数据在不同视图的计数、标题、状态、截止时间必须一致，差异要能用筛选条件解释。判定：明细之和 = 汇总数。 |
| P13 | 布局与输入形态 | 窄窗口、缩放、键盘操作可用；关键按钮不被裁切；Esc/Enter 行为符合预期。判定：1280/1024/800/375 四档无关键控件不可达。 |
| P14 | 可测试性与可追溯 | 关键动作可用 API/DOM 稳定断言；有构建标识与健康端点；日志能定位一次操作。判定：断言不依赖中文文案或像素；报障能带版本号。 |
| P15 | 安全注入 | 搜索、标题、备注、Markdown 正文中的 HTML/脚本不得执行；危险能力要有边界说明。判定：注入串只作为文本展示。 |

## 三、怎么用

1. 需求子句 × 维度 = 矩阵；每格只有三态：适用（给产出）/ 不适用（给理由）/ 未判断（不允许）。
2. 平台类维度不按子句展开，按**一次发布**逐条过。
3. 出了新类型缺陷就回补一个维度，重跑矩阵会自动标出新格子。
